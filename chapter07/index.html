Chapter 07. 네트워크 환경설정 실습 — ping과 연결 상태 확인¶

🎯 이 장에서 배우는 것¶

  • ping 명령어로 네트워크 연결 상태를 확인할 수 있다
  • 네트워크 문제 발생 시 단계적 진단 방법을 이해할 수 있다
  • ping 응답 결과를 해석하여 연결 품질을 판단할 수 있다

📚 핵심 개념¶

개념 1: ping 명령어¶

비유로 시작: "ping은 마치 친구에게 '야! 잘 있어?'라고 소리쳐서 대답을 듣는 것과 같아요"

전화를 걸 때 상대방이 전화를 받는지 확인하듯이, 컴퓨터도 다른 컴퓨터나 서버가 살아있고 연결 가능한지 확인해야 합니다. 이때 사용하는 도구가 바로 ping 명령어입니다.

ping은 'Packet Internet Groper'의 줄임말로, 네트워크상의 다른 장비에게 작은 데이터 패킷을 보내고 응답을 받아 연결 상태를 확인하는 명령어입니다.

graph LR A[내 컴퓨터] -->|ping 패킷 전송| B[목표 컴퓨터] B -->|응답 패킷 전송| A A -->|응답시간 측정| C[연결 상태 확인]

예시: ping 8.8.8.8 (구글 DNS 서버에 연결 테스트)

개념 2: ping 응답 해석¶

ping 명령어를 실행하면 다음과 같은 정보를 얻을 수 있습니다:

응답 시간(Response Time): 패킷이 목적지까지 갔다가 돌아오는 데 걸린 시간 (ms) - 1-30ms: 매우 빠름 (같은 네트워크) - 30-100ms: 보통 (인터넷 연결) - 100ms 이상: 느림 (멀리 있거나 문제 있음)

TTL(Time To Live): 패킷이 네트워크에서 살아있을 수 있는 시간 - 숫자가 클수록 더 많은 라우터를 거칠 수 있음

🔨 따라하기¶

Step 1: 자기 자신에게 ping 보내기¶

먼저 내 컴퓨터가 정상인지 확인해보겠습니다.

Windows에서: 

ping 127.0.0.1

실행 결과: 

Reply from 127.0.0.1: bytes=32 time<1ms TTL=128
Reply from 127.0.0.1: bytes=32 time<1ms TTL=128
Reply from 127.0.0.1: bytes=32 time<1ms TTL=128
Reply from 127.0.0.1: bytes=32 time<1ms TTL=128

💡 알아보기: 127.0.0.1은 'localhost'라고 부르며, 항상 자기 자신을 가리킵니다.

Step 2: 게이트웨이에 ping 보내기¶

네트워크의 출입구 역할을 하는 공유기에 연결을 확인합니다.

명령어: 

ping 192.168.1.1

실행 결과: 

Reply from 192.168.1.1: bytes=32 time=1ms TTL=64
Reply from 192.168.1.1: bytes=32 time=1ms TTL=64

Step 3: 외부 사이트에 ping 보내기¶

인터넷 연결 상태를 확인합니다.

명령어: 

ping google.com

실행 결과: 

Reply from 172.217.175.14: bytes=32 time=15ms TTL=115
Reply from 172.217.175.14: bytes=32 time=14ms TTL=115

Step 4: 연결 실패 상황 체험하기¶

와이파이를 끄고 다시 ping을 시도해보세요.

명령어: 

ping google.com

실행 결과: 

Request timed out.
Request timed out.
General failure.

📝 네트워크 진단 순서¶

flowchart TD A[네트워크 문제 발생] --> B[1단계: ping 127.0.0.1] B --> C{성공?} C -->|아니오| D[컴퓨터 문제] C -->|예| E[2단계: ping 게이트웨이] E --> F{성공?} F -->|아니오| G[로컬 네트워크 문제] F -->|예| H[3단계: ping 외부 사이트] H --> I{성공?} I -->|아니오| J[인터넷 연결 문제] I -->|예| K[네트워크 정상]

⚠️ 주의할 점¶

방화벽 차단: 일부 서버는 보안상 ping 응답을 차단할 수 있습니다. ping이 실패해도 실제로는 서버가 정상일 수 있어요.

지속적인 ping: ping -t 명령어로 계속 ping을 보낼 수 있지만, 상대방 서버에 부담을 줄 수 있으니 테스트 목적으로만 사용하세요.

✅ 점검하기¶

  1. ping 127.0.0.1이 실패한다면 어떤 문제일까요?
정답 확인컴퓨터 자체의 네트워크 기능에 문제가 있습니다. 네트워크 드라이버 재설치나 시스템 재시작이 필요할 수 있습니다.
  1. ping 응답 시간이 500ms라면 연결 상태가 어떤가요?
정답 확인매우 느린 연결 상태입니다. 네트워크가 혼잡하거나 목적지가 매우 멀리 있거나, 네트워크에 문제가 있을 가능성이 높습니다.
  1. ping google.com은 성공하는데 ping 8.8.8.8이 실패한다면?
정답 확인DNS는 정상이지만 특정 IP로의 라우팅에 문제가 있거나, 해당 서버가 ping을 차단하고 있을 가능성이 있습니다.

💡 생각해보기¶

실습 활동: 옆 친구의 컴퓨터 IP 주소를 물어보고 서로 ping을 보내보세요. 같은 네트워크에 있으면 매우 빠른 응답시간(1-5ms)을 확인할 수 있을 거예요!

도전 과제: tracert google.com 명령어를 실행해보세요. 여러분의 데이터가 구글까지 가는 경로를 한 눈에 볼 수 있답니다!
